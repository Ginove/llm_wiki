## 方案三：Ingest 管线并行化 — 计算/提交分离架构

### 目标
将 Ingest 队列从串行（1并发）提升为可配置并行（默认3，上限10），同时保证文件写入一致性。

### 核心思路

当前 `autoIngest()` 全程持有项目互斥锁（含所有 LLM 调用），导致队列串行。改造为：
- **LLM 计算阶段**（MinerU、Caption、分析、生成、审查）→ **无锁并行**
- **文件写入阶段**（writeFileBlocks + 合并）→ **按页面路径细粒度锁**
- **提交阶段**（index.md、log.md、缓存更新）→ **短暂提交锁**

```
任务A: [====== 无锁LLM计算 ======] [页锁:写] [提交锁:index/log]
任务B:      [====== 无锁LLM计算 ======] [页锁:写] [提交锁:index/log]
任务C:           [====== 无锁LLM计算 ======] [页锁:写] [提交锁:index/log]
```

### 变更清单

#### 1. 新建 `src/lib/page-write-lock.ts` — 按页面路径的异步互斥锁

```typescript
// 与 project-mutex.ts 相同的 promise-chain 模式，但 key 是
// `${projectPath}:${pagePath}`，只保护单个页面的 read-merge-write。
export async function withPageWriteLock<T>(
  projectPath: string,
  pagePath: string,
  fn: () => Promise<T>,
): Promise<T>
```

- 不同页面可并行写入，同一页面串行
- 防止两个并发 ingest 对同一 `wiki/concepts/foo.md` 的 read-merge-write 竞争

#### 2. 新建 `src/lib/commit-lock.ts` — 提交阶段短锁

```typescript
// 保护 wiki/index.md、wiki/log.md、ingest-cache.json 的 read-modify-write。
// 持有时间极短（纯 I/O，无 LLM 调用）。
export async function withCommitLock<T>(
  projectPath: string,
  fn: () => Promise<T>,
): Promise<T>
```

#### 3. 修改 `src/lib/ingest.ts` — 移除全局锁，改用细粒度锁

**3a. `autoIngest()` (line 572-583)**
- 移除 `withProjectLock` 包裹，直接调用 `autoIngestImpl`
- 锁的粒度下放：计算阶段无锁，写入/提交阶段用细粒度锁

**3b. `executeIngestWrites()` (line 3217-3227)**
- 同样移除 `withProjectLock`，改用细粒度锁

**3c. `writeFileBlocks()` (line 1788)**
- 在每个内容页的 `mergePageContent` + `writeFile` 外层包裹 `withPageWriteLock`
- log.md 的 append 操作也包 `withPageWriteLock`（同一文件可能并发 append）
- 这样不同页面的写入并行，同一页面的写入串行

**3d. 提交阶段（index.md / log.md / cache）**
- `updateWikiIndexDeterministically` (line 1235) → 包 `withCommitLock`
- `wiki/log.md` 确定性写入 (line 1249-1261) → 包 `withCommitLock`
- `saveIngestCache` (line 1333) → 包 `withCommitLock`

**3e. Embedding 循环并行化 (line 1345-1359)**
- 当前 `for (const wpath of writtenPaths) { await embedPage(...) }` 串行
- 改为 `Promise.all` + `createAsyncLimiter(embCfg.concurrency)` 并行
- embedding 后端本身有 limiter，这里只需并行发请求

#### 4. 修改 `src/lib/ingest-queue.ts` — 队列并行化

**4a. 状态重构**
```typescript
// 替换前:
let processing = false                              // 全局串行标志
let currentAbortController: AbortController | null  // 单任务 abort
let lastWrittenFiles: string[]                      // 单任务文件追踪

// 替换后:
const activeTasks = new Map<string, {
  abortController: AbortController
  writtenFiles: string[]
}>()                                                 // 按 taskId 追踪
let maxConcurrentIngests = 3                         // 可配置并发上限
```

**4b. `processNext()` 改造 (line 658)**
- 移除 `if (processing) return` 串行守卫
- 改为：检查 `activeTasks.size < maxConcurrentIngests`，有空间则启动新任务
- 每个任务完成后（success/fail），触发 `processNext` 启动下一个
- 队列排空（所有 pending 完成 且 activeTasks.size === 0）时触发 drain sweep

**4c. `cancelTask()` (line 303)**
- 按 taskId 从 `activeTasks` 查找并 abort，不再依赖全局 `currentAbortController`
- 清理该任务的 `writtenFiles`

**4d. `pauseProcessing()` (line 388)**
- abort 所有 active tasks，将所有 processing 状态改回 pending

**4e. `cancelAllTasks()` (line 353)**
- abort 所有 active tasks

**4f. `pauseQueue()` (line 500)**
- abort 所有 active tasks，flush 状态到磁盘

**4g. 429 限流处理**
- 任一任务触发 429 时，仍暂停整个队列（保持现有行为）
- 所有 active tasks 被 abort 并回到 pending

### 不改动的部分

| 模块 | 原因 |
|---|---|
| `project-mutex.ts` | 保留 `withProjectLock` 供其他调用方使用，但 `autoIngest` 不再使用它 |
| Caption 管线内部并发 | 已有 `mmCfg.concurrency` 控制，无需改动 |
| Embedding limiter | 已有 `embCfg.concurrency` 控制，无需改动 |
| Dedup 队列 | 独立模块，本次不动 |
| Agent 循环 | Rust 后端，业务逻辑决定串行 |
| 长文档分块分析 | 串行是滚动 digest 依赖决定的，改为 map-reduce 是另一个优化 |

### 并发安全性分析

| 共享资源 | 风险 | 保护机制 |
|---|---|---|
| `wiki/index.md` 读取（prompt 上下文） | 读到旧版本 → 可能生成重复页面 | **可接受**：merge 逻辑处理重复，质量略降但不出错 |
| `wiki/index.md` 写入 | 并发覆盖 | `withCommitLock` |
| `wiki/log.md` append | 并发交错 | `withCommitLock` |
| 内容页 `wiki/concepts/*.md` | read-merge-write 竞争 | `withPageWriteLock` |
| `wiki/sources/<slug>.md` | 不同 source 不冲突 | source-scoped，天然隔离 |
| `wiki/media/<slug>/` | 不同 source 不冲突 | source-scoped，天然隔离 |
| `ingest-cache.json` | read-modify-write 竞争 | `withCommitLock` |
| `image-caption-cache.json` | 并发写入 JSON 损坏 | `withCommitLock`（将 cache 保存移入提交阶段） |
| `ingest-queue.json` | 队列状态一致性 | 内存中单线程操作 + `saveQueue` 串行 |
| 长文档 checkpoint | 不同 source 不冲突 | source-scoped，天然隔离 |
